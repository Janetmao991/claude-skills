# 出片前两道检查：机检 + 独立审片

借自花叔 huashu-art-motion 的 deliver / 独立审片（2026-10-28 加）。每次渲染出要给 Janet 看的版本前做，顺序：机检 → 审片 → 改 → 重渲 → 再给 Janet。

为什么要别人来审：做片子的人知道每一镜「想表达什么」，看的时候会自动脑补，看不到观众真正看到的东西。一个没参与制作、只看成片的 agent 不会脑补。

## 1. 机检

```sh
uv run <skill>/scripts/film_check.py <成片.mp4> --project <项目> --sheets
```

查四样：最长画面没变化（>5 秒黄、>8 秒红）、空白帧、蓝色、镜头推近密度（读 `assets/camera-keys.js`）。结果写进 `<项目>/审片/机检.md`，`--sheets` 每 2 秒抽一帧拼成 contact sheet 存到 `<项目>/审片/sheets/`，给审片用。红灯先改，改完重渲再跑。

阈值是按 Janet 自己的片子定的（Embedding 横屏前两分钟：无质感版最长 8.9 秒没变化，她嫌闷；手绘质感版 3.0 秒，她保留）。花叔的 `film_gate.py` 把 Janet 认可的这支片判成红灯（它是按花叔的口味标定的，固定标题和进度链在它那里算「翻页式 PPT」），所以不用它当门禁。

## 2. 独立审片

用 Agent 工具派一个新 agent（不要 fork，它不能看到制作过程），把下面这段填好发给它。审片人只读 contact sheets 和字幕原文，**不读场景代码、不读 SCRIPT 的写作说明**。

```text
你是这支 AI 术语讲解视频的审片人，没参与制作。只看成品，挑观众会卡住或会觉得不对的地方。

材料：
- contact sheets：<项目>/审片/sheets/sheet_*.png（每 2 秒一帧，左上角是时间码）
- 字幕原文和时间：<项目>/assets/vo/timeline.js（window.__VO，每句的 id、文字、起止秒）
- 机检结果：<项目>/审片/机检.md
- 一手数据：<项目>/assets/real-data.js（屏幕里的数字应该都来自这里）
看不清的地方，用 ffmpeg -ss <秒> -i <成片.mp4> -frames:v 1 抽一张全尺寸的看。

逐条查，每个问题写：时间码｜看到了什么｜为什么是问题｜建议怎么改：
1. 字出框、被镜头裁成半截、压线、标签互相重叠、字幕把英文单词从中间断开。
2. 纸上屏幕：手写结论里的数字和屏幕里显示的对不对得上；高亮框是不是真的框住了那个数字；一个屏幕是不是只证明一件事。
3. 数字：屏幕和手写字里的每个数字，在 real-data.js 或台词里找得到出处吗。
4. 画面和台词：这句台词说的东西，这时画面上有没有；有没有画面抢在台词前面太久，或者台词说完很久才画出来。
5. 品牌：有没有蓝色（公司真 logo 除外）、有没有第三种强调色、有没有加粗强调（应该用手绘圈 / 下划线 / 荧光笔）、有没有角色或吉祥物。
6. 节奏：有没有连续 5 秒以上画面完全没变化；镜头是不是推得太勤、推进去不拉回。
7. 看完这一段，一个不懂技术的人能不能用一句话复述这个术语是什么。不能的话，卡在哪一秒。

最后给一个 1–10 分和三条最该改的。把全文写进 <项目>/审片/审片-<日期>.md，然后回复我同样的内容。
```

## 3. 改完之后

- 审片的问题逐条处理，改了的写「已改」，不改的写理由，追加在审片文件末尾。
- **改完要复查，不能改完就交**（2026-10-30 加）：重渲后再跑一次机检；再对每个「已改」的时间码用 `ffmpeg -ss <秒> -i <成片> -frames:v 1` 抽一帧，用 Read 打开确认真的改好了、没把旁边弄坏。改动超过 3 处画面时，再派一个**新的**审片人（不要用上一个，它记得旧版）只看改过的时间段。
- 最多 3 轮。第 3 轮还有红灯或没解决的问题，照样把片子给 Janet，但在 REVIEW.md 和给她的话里列清楚还剩哪几条、在哪一秒。
- 机检黄灯和审片结论的摘要写进项目的 REVIEW.md，再把片子给 Janet。
- 这一期做对了的事（Janet 夸过、审片说好的），记到 `references/visual-direction.md` 或 `production.md` 对应的地方，写清做法和为什么，下一期照着做。
