Granola 是怎么
做出来的

一场 Zoom 会议从你的扬声器流出，到变成一份"像你写的、但更完整"的笔记，中间经过 6 层技术。几乎每一层都是买来的通用零件，Granola 的功夫花在拼装和打磨上。

黑字是你在会上随手打的，灰字是 AI 从转写里补的。真实产品里每行旁边有放大镜，点开能看到它来自转写的哪一段。（示例内容）

1
Client

桌面 App：Electron 外壳 + 原生"手脚"

要解决的问题

一套代码同时跑 Mac 和 Windows，界面好看、迭代快，同时还能碰到系统底层（音频、日历、权限）。

怎么做的
主体是 Electron 44，界面用 React + TypeScript已确认 · 安装包。和系统打交道的是十几个原生插件：抓音频、读 Zoom 窗口判断谁在说话、列出谁在用麦克风、读 Apple 日历、本地区分说话人（Swift 写的）、一个能在你视频上叠水印的虚拟摄像头，以及加密的本地数据库。
白话
Electron 就是把一个网页（Chrome 内核）打包成桌面软件，Slack、Notion、VS Code、Cursor 都是这么做的。网页本身碰不到麦克风底层，所以要用系统语言写几个小插件，网页通过接口调用它们。Electron 是脸和大脑，原生插件是手脚。
为什么这么选

工程师只有 25–30 人，速度第一。评估过更轻的 Tauri，没看到明显性能提升就没换。代价是吃 CPU，以及一类 Electron 特有的安全漏洞（见下文"安全"）。

2
Capture

不进会议，怎么听到声音？

要解决的问题

Otter、Fireflies 派一个"机器人"以参会者身份进会议。Granola 什么都不加入，要直接在你电脑上拿到"我说的"和"别人说的"。

怎么做的
你的声音直接录麦克风。别人的声音最终会从你的扬声器播出来，Granola 就在系统声音输出那里"接一根管子"：macOS 14.2+ 用苹果的 Core Audio Process Tap，老系统用 ScreenCaptureKit已确认 · 安装包。没有装虚拟声卡驱动。Windows 大概率用 WASAPI loopback推断。
看一眼
麦克风
= Me
系统声音
= Them
我们这季度预算主要卡在安全审核上。
明白，SOC 2 报告我周五前发你。
白话
"Me / Them" 不是 AI 听出来的，是物理上就分开了：麦克风那路是你，系统声音那路是别人。一刀最重要的切分，不用任何 AI 就完成了。

回声消除（AEC）：不戴耳机时，别人的声音从扬声器出来又被你的麦克风收进去，同一句话会被转写两遍。Granola 在本地用开源的 WebRTC AEC3（谷歌给视频通话做的那套）把它减掉。创始人举的例子是：开到一半摘耳机，系统要马上适应。
怎么知道开会了

三个信号叠加：日历上有会、某个会议 App 开始用麦克风、辅助功能读到 Zoom/Teams 窗口。会议 App 不再用麦克风，或 15 分钟没有新声音，就算结束。

代价

为了"无机器人"，早期只有 macOS 13.4 以上能用，创始人说大概只覆盖 15% 的 Mac 用户，"非常痛苦"。另外，电脑放音乐也会被转进去；线下会议一屋子人都算"Me"；而"别人不知道它在录"正是被起诉的那一点。

3
Transcription

语音转文字：买最好的，同时接两家

怎么做的
默认 Deepgram Nova-3，备选 AssemblyAI已确认。从你的电脑直接开一条 WebSocket 连到 Deepgram，每路音频一条，16kHz 单声道。App 先向 Granola 后端要一个临时 token 再去连，长期密钥不放在用户电脑上。还设了"不许 Deepgram 拿我们的音频训练模型"。音频不保存，边听边转，转完就扔。
白话
流式 vs 批量：流式是边说边出字（像直播字幕），批量是录完整段再转（更准但要等）。桌面端用流式，手机端因系统限制只能录完再转。

WebSocket：普通网页请求是"问一次答一次"，WebSocket 是"电话一直不挂"，适合源源不断地送音频。

说话人分离（Diarization）：判断每句话是谁说的。创始人说实时版还不够好，而且"错误的说话人标签比没有标签更让模型困惑"。所以 Granola 直接读 Zoom 界面上谁的头像在亮来标名字。
新发现

你的电脑上已经下载了一个 233MB 的 NVIDIA Parakeet 语音模型，对应一个未公开宣传的 Labs 功能"本地转写：离线可用，仅英文"已确认 · 本机。这笔业务里最大的成本，正在被往用户电脑上推（见下文成本计算器）。

4
Notes · 产品的灵魂

AI 写笔记：把"判断重要性"交还给用户

拼进 prompt 的
材料作用
你会上打的几行 bullet重要性信号，最关键
带 Me/Them 标签的转写细节来源
日历：标题、参会人场景
你是谁、什么职位、对方是谁决定写什么、怎么写
模板（Auto / 客户访谈 / 1:1 / 自定义）结构
白话
大模型最难的不是"总结"，是判断什么重要。一小时会议大半是寒暄和重复。你随手打的"定价太高？"就是在告诉 AI"这个我在意"。于是一个难问题（判断重要性）变成了一个简单问题（围绕这几点扩写）。往上翻到页首，切换那个按钮就是这个效果。
模型

"主要是 OpenAI 和 Anthropic 的混合"已确认，供应商名单里还有 Google、xAI、Fireworks。用户不能选写笔记用哪个模型：每换一个模型 prompt 都要重调，才能保持"Granola 的味道"。聊天功能付费用户可以选。

Prompt 哲学

别写一堆 if-then 规则，规则多了必然互相打架。像给新员工布置任务那样给背景：你的目标、这份工作的目标、这场会的目标。结果 prompt 变得更短、更针对个人。他们还按"职位 × 会议类型"做了大量预设：同一场融资路演，VC 和创始人拿到的笔记完全不同，因为你通常更在意对方说了什么。

换模型的流程
Evals（评测） 是 AI 产品的自动化考试：准备一批真实会议和理想笔记，每次换模型、改 prompt 都考一遍。Granola 用 Braintrust 做评测，新模型出来"跑一遍评测，好就热切换"。

为什么不自己训练模型？创始人的说法：基础模型进步太快，用好现成最强的模型还有大量红利，撞墙了再自己训。早期上下文窗口只装得下 30 分钟会议，他们选择等模型变大，没去写复杂的切片逻辑。
5
Memory

跨会议问答：从笔记本到"会议记忆"

用户问："过去三个月所有客户提到的 bug 有哪些？" 答案散在几十场会里。Granola 的做法换了三代：

2023 – 2025 初

长上下文硬塞

把相关会议全部贴进模型的"工作记忆"。贵，会议一多就装不下。

为什么不先用 RAG

"最有意思的问题"搜不到

普通搜索能"查找"，但答不了"哪里我没讲清楚？"这种要看全貌的问题。他们愿意先承担成本。

2026-04 起

Agent：搜 → 筛 → 读 → 再搜

像研究员：先扫 100 份笔记，挑出可能相关的，再细读那几场的原始转写。复杂问题要想约 38 秒。

关键算账

转写的字数约是笔记的 10 倍，所以 agent 先读 100 份笔记，而不是 10 份转写：花同样的钱，覆盖面大十倍已确认 · 官方博客。回答时附上"我看了哪些会、哪里可能不完整"，防止 AI 自信地答错。

白话
RAG：先搜，再把搜到的几段给模型看。好比开卷考试先翻目录找页码。
Embedding / 向量：把一段话变成一串数字，意思相近的数字也相近，所以搜"价格太贵"也能找到"预算不够"。
向量数据库：专门存这些数字、能快速找"最相近"的数据库，Granola 用的是 Turbopuffer。
Agent：不是一次性回答，而是自己决定下一步搜什么、读哪篇、够不够，循环到满意为止。
会前简报

大量会议都会提前生成简报，但只有约 10% 被打开。创始人管这叫"扶手"：平时看不见，你迟到两分钟急需时它必须已经在那。这是在用钱换速度。

6
Platform

后端与 MCP：把会议记录变成其他 AI 的燃料

后端

AWS（仅美国区）· Postgres · TypeScript/Node · Terraform · ClickHouse · Stripe · Twilio已确认。一套非常标准的 SaaS 技术栈，这本身就说明：工程精力全花在用户能感知的地方。

平台层

REST API（2026-02 发布 v1.0，10 月已到 v1.6）、Webhooks（有新笔记时主动通知你的系统）、MCP Server mcp.granola.ai/mcp。

白话：MCP
MCP（Model Context Protocol） 可以理解为 AI 助手的 USB 接口。Granola 提供一个 MCP 服务器，挂着一份工具菜单（列出我的会议、读这场会的转写、用自然语言问我的会议）。Claude、ChatGPT、Cursor 插上就能用。你现在用的 Claude 就连着 Granola 的 MCP。
战略意义

2026-03 Granola 把本地缓存加密，社区里读本地文件的小工具全部失效，a16z 的人公开批评它"变封闭"。CEO 回应"这是我们的错"，随后推出官方 API 和 MCP，而 API 只给 Business 及以上。数据出口从后门改成了收费的正门，也就是 deepdive 里"从笔记本到企业会议记忆层"在技术上的落地。

Security & Legal

两次漏洞和一场官司，都能从架构里找到原因

2025-03 · Tenable 发现

密钥藏在"功能开关"里

研究员把 Electron 安装包解压（里面基本是能直接读的 JavaScript），找到一个不用登录就能访问的接口 /v1/get-feature-flags，返回内容里有一把 AssemblyAI 的 API 密钥，能下载约 300 位 iOS 内测用户的转写。教训：长期密钥永远不要发到用户设备上。

2026-06 · Strix 发现

点一下就被接管账号

攻击者把显示名设成一个链接 → 它出现在受害者的动态里 → 受害者一点，Electron 主窗口跳到攻击者网页 → 给自家页面开的"系统接口"还挂在窗口上，攻击者网页就能拿到登录 token 和本地数据库密钥。Electron 的经典坑：网页内容和系统权限住在同一个窗口里。6 天内修复，没有被利用的证据。

2026-07-30 · Chamberlain v. Granola

官司的三个技术要点

① 实时转写 = 音频在通话进行中就流到转写商，原告认为符合窃听法"同时截获"的要件。② Granola 其实做了告知功能（聊天里自动发消息、视频水印），但默认都是关的。③ 免费版和 Business 版默认用数据训练模型，训进去的删不掉。2026-08 Otter 案判决认定"为自己目的拿录音训练的供应商 = 第三方窃听者"，这让"训练默认开"成了最要命的那个开关。

回到投资视角

每一层能被复制吗？

层自研程度被复制的难度
1 桌面 App低，标准框架容易
2 抓音频 + 回声消除中，系统接口 + 开源，但工程细节多要踩几个月坑，大厂能做
3 转写低，买的容易
4 写笔记中高，prompt × 职位 × 会议类型的调优 + 评测体系形式好抄、味道难抄，但模型越强这份积累越不值钱
5 跨会议问答中，agent + 向量库标准做法，模型公司自己也在做
6 平台技术低，数据位置高技术好抄，企业的会议历史搬不走

和 deepdive 的判断一致：技术本身不是护城河，真正在积累的是第 6 层的"数据引力"。接下来最值得盯的两个技术信号：本地转写会不会改写成本结构，通知默认值会不会被官司逼着打开。

带走的东西

AI 应用公司的 9 个通用架构模式

分析别的公司、或者自己做产品时都会反复遇到。

  1. 买零件，拼体验。模型、转写、向量库、云全买现成的，自己只做用户能感知的那 10%。分析一家 AI 公司，先问"哪一层是你自己造的"。
  2. 能用物理结构解决的，别交给 AI。Me/Them 靠两路音频天然分开，不让模型去猜。
  3. 让用户顺手给出"重要性信号"。几行 bullet 把难问题变成简单问题。
  4. 模型可替换，评测先行。不绑定任何一家，靠 evals 随时切换。这是应用层公司防止被模型商吃掉的基本功。
  5. 等平台，别硬造。上下文不够就等它变大，押注"一年后更便宜、更强"。
  6. 长上下文 → RAG → Agent。几乎所有"在大量资料里问问题"的产品都在走这条路。
  7. 用户设备上只放临时 token。长期密钥永远留在后端。
  8. Electron 的安全边界。网页内容和系统权限不能住在同一个窗口。
  9. 平台化 = API + MCP。把自己的数据开放给其他 AI，从"一个工具"变成"一层基础设施"。
