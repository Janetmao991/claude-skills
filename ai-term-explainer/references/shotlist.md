# 镜头表（SHOTLIST.md）：先镜头表，再写场景

借自花叔 huashu-art-motion 的「先镜头表，再动手」（2026-10-28 加）。SCRIPT.md 定稿、配音之前或之后都行，**写场景代码之前**必须有。

为什么：脚本只管「说什么」，镜头表管「观众看到什么」。一行一个画面事件，写得出「什么东西在做什么」，这一段才不会变成一页越堆越长的字；写不出的那一行，说明还没想好怎么画，先别写代码。在表上改一行只要几秒，做成动画再返工要半小时。

## 写法

在项目根目录建 `SHOTLIST.md`：

```markdown
画板：whiteboard
强调色：粉 #E5466E + 黄荧光
角色：无

| 时间段 | 台词 | 画面里的物 | 它在做什么 | 右栏 | 镜头 | 屏上字 |
|---|---|---|---|---|---|---|
| 0–4 | h1 | 顾客那句话 | 被手写在纸上，「钱」字被粉圈住 | | 停 | 我买的东西不想要了 |
```

| 列 | 写什么 | 不要写 |
|---|---|---|
| 时间段 | `0–4`、`1:20–1:26`。按配音 timeline 填；还没配音就按每秒 4 个字估 | |
| 台词 | 对应 SCRIPT 里的句子 id（`h1`、`s3–s5`），可空 | |
| 画面里的物 | 左栏手绘类比里的**一个具体的东西**：一页文档、顾客那句话、一个坐标点、一台翻译机 | 标题、要点、文字、列表、背景、图标、金句 |
| 它在做什么 | 这个东西自己的动作：被画出来、被切成小块、滑进坐标图、被粉圈住 | 出现、显示、展示、淡入、逐条出现 |
| 右栏 | `纸上屏幕：<证明哪件事>`、`补充手绘：<什么>`，或空 | 一屏证明两件事 |
| 镜头 | `停` / `轻推` / `拉回` / `转右栏` / `切` | 每行都推 |
| 屏上字 | 这一行新写出来的手写字或手写结论，≤12 字最好，最多 20 | 整句口播（交给字幕） |

## 规则（lint 会查的）

- **表前三行**：画板（5 套之一，和上一期不同）、强调色（只有粉 + 黄荧光，写了蓝色红灯）、角色（无）。
- **一行 3–8 秒**：超过 8 秒黄、超过 12 秒红。对应品牌规范「每 3–5 秒画面要有新东西」。
- **第一行是一个真实场景里的东西在动**，不是标题。
- **文字主导的行 ≤30%**：屏上字超过 12 个、或物是标题 / 大字 / 金句，都算文字主导。
- **纸上屏幕的手写结论要带一个真数字**（「按字搜 **0** 条结果」）；加 `--project` 时，屏上字里的每个数字都要在 SCRIPT.md 或 assets/real-data.js 里找得到。
- **镜头是标点**（花叔 `references/镜头语言.md`）：观众在读字、画面自己在动时，镜头停住；只在换想法时轻推；连着三次往里推不拉回，黄；推镜超过每分钟 6 次，黄。
- **相邻两行不要同一个物 + 同一个镜头**：构图没变，观众会觉得卡住了。

lint 查不了、要自己对的：全片是不是一个例子贯穿到底（第 1 期是「顾客想退款」那一句）；纸上屏幕是不是一个镜头只证明一件事。

## 检查

```sh
python3 <skill>/scripts/shotlist_lint.py <项目>/SHOTLIST.md --project <项目>
```

红灯就改表、重跑，**红灯清掉再写场景**。黄灯可以做，在 REVIEW.md 写一句为什么。
