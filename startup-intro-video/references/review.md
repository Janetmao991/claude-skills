# 独立审片（两轮）

全片渲染后、给 Janet 看之前，跑两轮"独立审片 → 修改"。目的是让 Janet 拿到的版本已经过一遍挑错，她的时间花在判断方向上，而不是抓错字和卡帧。

做片的 agent 看自己的作品容易替它找理由，所以审片交给全新的子 agent。每轮同时派两个，分工不同：

| 审片人 | 看什么 | 拿到的材料 |
|---|---|---|
| A 综合审片 | 事实、完整度、术语、原声、画面、技术故障 | 全部：脚本、帧拼图、research、框架 |
| B 新观众 | 没听过这家公司的人能不能一路跟上 | **只有** `narration.md` |

B 对这类片子尤其重要：它的首要标准就是"新观众能看懂"。A 为了核对事实要读 research，读完就懂这家公司了，会在脑子里自动补上视频没讲的那一步。B 只知道观众知道的东西，哪里接不上一读就卡住。

## 流程

**固定两轮，第二轮修完就交给 Janet。** 第二轮之后还有问题，写进交付说明由她决定，不要继续自己循环。

每一轮：

1. 生成审片材料：

   ```bash
   python3 tools/review_pack.py renders/<当前版本>.mp4 review/round-<N>
   ```

   默认每 3 秒一帧（23 分钟约 24 张拼图）。片子短于 10 分钟加 `--step 2`。

2. 在同一条消息里启动 A 和 B 两个全新的子 agent（Agent 工具，`general-purpose`，不要 fork，不要 SendMessage 给上一轮的审片人），分别发下面两份任务书。**不要告诉它们你认为哪里好、改过什么、上一轮发现了什么。** 第二轮也全部换新的。给 B 的任务书里不要提公司背景，也不要附其他文件路径。
3. 拿到 `findings.md`（A）和 `findings-flow.md`（B）后，自己逐条核实：去看对应的帧、台词和出处。审片人也会看错，不要照单全收。B 说"没跟上"的地方，默认是真问题：它就是观众。
4. 修改，把两份发现的处理结果都写进 `review/round-<N>/fixes.md`：每条写"已改 / 不改（原因）/ 留给 Janet"。B 卡住的地方，优先补一句解释或过渡，而不是把句子写得更长。
5. 台词改了就重新配音，跑 `build.py` 和 `check_cues.py`，用新的输出名重新渲染（上一版确认被取代后放进废纸篓），再进入下一轮。

第二轮修完后，确认第一轮修好的问题没有复发，再交付。

## 交付给 Janet 时附上

几句话说明：两轮一共发现和修了什么（最重要的几条）、哪些没有改以及原因、哪些需要她拍板。还要说明审片人听不到声音，配音的语气和节奏仍要她听。

## 任务书 A：综合审片

把尖括号替换后整段发给子 agent：

```
你是这条视频的独立审片人，和制作团队没有关系。你的任务是找出问题，不是肯定这条视频。

这是一条介绍 <公司> 的视频，目标观众没听说过这家公司，也不懂这个行业的术语。
开场提出的问题：<开场问题>

材料（图片用 Read 可以直接看）：
- 成片：<video 绝对路径>/renders/<版本>.mp4（Read 打不开视频。需要看某一刻的帧时，用 ffmpeg -ss <秒> -i <成片> -frames:v 1 <输出.jpg> 抽出来再看）
- 脚本：<video 绝对路径>/script.json，原声：<video 绝对路径>/clips.json
- 审片包：<video 绝对路径>/review/round-<N>/
  - timeline.md：每章每段的时间和文字，标了旁白还是原声
  - sheet-*.jpg：帧拼图，每格左上角是时间
  - cuts-*.jpg：换章和进出原声前后的帧，每格左上角标 before / after 和时间
  - tech.md：时长、音量、静止段、没写完的章、配音听写报告
- 事实依据：<项目绝对路径>/research/ 和 <项目绝对路径>/<公司> — Framework.md
- 标准：~/.claude/skills/startup-intro-video/references/framework.md 和 visual-style.md

你看不到动态、也听不到声音，只能从帧、台词和报告判断。判断不了的写"无法判断"，不要猜。

按这个顺序审：

1. 事实：抽查脚本里的数字、日期、人物说法和因果判断，能否在 research/ 找到依据？有没有把推测说成事实、把事后总结说成当时的打算，或把两个人的话说成有分歧（其实是一个意思）？列出查了哪些。
2. 完整：对照 framework.md 的十一章和必答清单，哪一章太薄、哪个必答问题没回答？开场问题在结尾有没有得到回答？
3. 术语：哪个术语、缩写、人名、公司名第一次出现时没有解释？列出时间。
4. 原声：每段原声是否由前一句旁白铺垫、后一句承接？它证明的是旁白说的那个点吗？画面里是说话的本人吗？名牌上的姓名、职位、节目、日期和 clips.json、research 一致吗？中文翻译（如果有）和英文对应吗？
5. 画面：哪一屏像 PPT（一个标题加几个要点）？哪个画面和这一刻的旁白无关？哪一屏停太久没变化？文字有没有重叠、出框、换行错位、被字幕挡住？有没有画面中间的第二条字幕？品牌色和 logo 用得一致吗？重建的界面和示意图有没有标"示意"？
6. 技术：tech.md 里有没有还在用占位画面的章？切点前后有没有卡住、闪帧、黑帧？静止段里哪些是真问题？音量是否正常？

把结果写到 <video 绝对路径>/review/round-<N>/findings.md，每条一行：

| 严重度 | 时间 | 类别 | 问题 | 依据 | 建议 |

严重度：必须改（事实错误、明显故障、新观众一定看不懂）/ 建议改 / 请 Janet 判断（取决于品味）。按严重度排序，最多 30 条，宁缺毋滥，不要为了凑数挑小毛病。

文件最后写两三句总体判断：这条视频最大的问题是什么。
```

## 任务书 B：新观众

把尖括号替换后整段发给子 agent。**只附 narration.md 一个文件。**

```
你是一位普通观众，第一次看这条视频。你没听说过视频里的公司和人物，也不了解这个行业的术语，但愿意认真看完。你只能看一遍，不能倒回去。

这条视频的全部旁白和原声字幕在：<video 绝对路径>/review/round-<N>/narration.md
（标了【播客原声】或【Podcast clip】的，是受访者本人说的话。）

只读这一个文件，不要读同一文件夹或项目里的其他文件，不要上网查这家公司。你知道的，只能是视频已经告诉你的。

做法：

1. 从头往下读，读到每一句时，只用前面已经讲过的内容去理解它，不要往后看。
2. 遇到下面这些情况就停下来记一条：
   - 出现一个人名、公司名、术语或缩写，前面没交代它是什么
   - 这句话和上一句之间缺了一步：为什么突然讲这个？"所以""因此"前后其实推不出来
   - "他""这个""这种做法"指的是什么不清楚
   - 一个数字出现了，但不知道它算多还是算少、说明了什么
   - 原声和前后旁白接不上：引用它是想证明什么？
   - 同一件事在不同地方用了不同的叫法，让人以为是两件事
   - 话题转到下一部分时没有过渡，你一时不知道现在在讲什么
   - 一段话太长太密，读到一半已经忘了开头
3. 每一条写：你卡在哪、你当时以为是什么意思、缺了哪句话就能跟上。只记真的让你卡住的地方，读得顺的不用夸。

读完后，合上文件（不要再看），凭记忆回答：
- 这家公司是做什么的？用两三句话讲给朋友听。
- 视频开头提了一个什么问题？最后的答案是什么？
- 这家公司最特别的地方是什么？
- 它最大的风险是什么？
- 哪一部分你最没听懂？

把结果写到 <video 绝对路径>/review/round-<N>/findings-flow.md：

先写上面五个问题的回答，然后是问题表，每条一行，按播放顺序：

| 严重度 | 时间 | 卡在哪 | 我当时的理解 | 缺了什么 |

严重度：看不懂（不补就跟不上后面的内容）/ 有点跳（能猜到，但要停一下）。最多 30 条。
```

B 的复述是最好的检验。它讲不出这家公司是做什么的，或者复述的"最特别的地方"和脚本想讲的对不上，说明结构本身有问题，要回头调整那几章的顺序和铺垫，不是改几句话能解决的。

英文版的片子，两份任务书照样用中文发，审片人读英文材料、用中文写结果，方便 Janet 看。
