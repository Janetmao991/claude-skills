# 框架和脚本

## 一条线

先写两句话，写不出来就别往下做：

- **开场问题**：一个反常识的事实引出的问题。Clay："它一条数据都没有，估值却是卖数据的 ZoomInfo 的五倍。投资人到底在为什么付钱？"
- **一句话答案**：结尾要落在这里。

每章开头用一句话接上一章（"So how does the table actually work?"），让观众知道为什么现在讲这个。

## 十一章

章 id 是 `script.json` 里的 `id`，也是场景组件的名字。比重是 Clay 那期各章的字数占比，只是参考：哪章料多哪章长，但别让某一章只剩一两句。

| 章 id | 讲什么 | Clay 那期怎么讲的 | 比重 |
|---|---|---|---|
| `hook` | 一个反常识的事实 + 开场问题 | 没有数据，估值 71 亿，是 ZoomInfo 的五倍 | 2% |
| `problem` | 客户原来的日子：没有这家公司时，这件事有多麻烦 | 你卖软件给公司，手上一张名单，要查十几个网站 | 4% |
| `what` | 它是什么（用一个比喻）、谁在用、用了以后怎样 | "一张自己会填的表格"；客户分三类；点名几家；一段客户原声 | 10% |
| `origins` | 创始人、早期走的弯路、第一批用户是谁、增长曲线 | 2017 年成立，摸索多年；第一批用户是冷邮件代理商；没做付款功能，手动发账单 | 8% |
| `product` | 产品怎么运作（走一遍）、为谁设计、怎么收费 | 每一列是一个动作；给技术型运营用，不给销售用；按用量收费、不限人数 | 7% |
| `gtme`（每期换名） | **这家公司最特别的一件事**，讲透 | 它造出的新职业 GTM engineer：三个人的活变一个人、六步工作流、数据能不能信、Clay 自己怎么用 | 26% |
| `moat` | 别人能不能抄：对每个主要对手逐个比，哪些抄不走，弱点在哪 | 对 ZoomInfo 有优势、对 Apollo 没有；抄不走的是合同、调度经验、社区；八种护城河打分；弱点是按量计费 | 12% |
| `position` | 它怎么描述自己，这个说法怎么变的 | 两个阶段，从"数据工具"到"行动系统" | 5% |
| `model` | 怎么赚钱、现在的价格、投资人买的是什么故事、估值怎么比 | 两位创始人从两个角度说同一件事；Sequoia 的说法；市销率对比 | 12% |
| `risk` | 最大的风险，上下游各一个，正反两边都给 | 被上面的数据仓库和下面的 Claude Code 绕过；供应商断供 | 8% |
| `verdict` | 回答开场问题 + 接下来看哪三个指标 | 在和模型进步赛跑；三件要盯的事 | 4% |

"最特别的一件事"那章占了四分之一，因为它是这家公司区别于同类的地方，也是观众看完会转述的内容。定框架时先想清楚这一章讲什么。它的位置可以调，通常放在产品之后。

## 必答清单

这些是 Janet 看 Clay 那期时追问的问题。观众也会问，脚本里要有答案：

- **客户到底是谁？** 分几类，各举真实的名字。只说"一万七千家公司"不够。
- **第一批用户是谁，怎么找到的？** 要有具体的故事和细节（Clay：没有付款按钮，手动发账单）。
- **产品的核心承诺靠得住吗？** 观众最容易怀疑的那一点，正面回答，最好让创始人自己说（Clay：数据准不准）。
- **产品的关键机制具体怎么算的？** 别停在"AI 打分"，说清规则是谁写的、举一个例子。
- **什么抄得走，什么抄不走？** 分开列。
- **现在卖多少钱？** 写当前价格，注明日期。
- **上游有没有风险？** 供应商、平台、合规。
- **引用两个人的话时，他们是在说同一件事还是有分歧？** 说准。Clay 那期早期版本把"一个观点的两个角度"写成了"两人意见不同"，Janet 纠正过。

## 新观众规则

- 每个术语、缩写、人名、公司名，第一次出现时用半句话交代它是什么。"Apollo is another contact-data company"、"A seat is one person's login"。
- 数字要有参照物：五倍于谁、相当于什么。
- 写完自己过一遍：把每个专有名词圈出来，往前找它第一次出现的地方，那里有没有解释。
- 定稿前列一张术语表放进 Framework，审片时对照。

## 写法

- 口语，短句，一句一个意思。旁白是说出来的，不是读出来的。写完念一遍，绕口就改。
- 数字写成念出来的样子（英文 "seven point one billion dollars"；中文"七十一亿美元"），配音不会读错，字幕也自然。
- 不把事后总结说成当时的策略，不把推测说成事实。这一条和口语表达的细则见 `~/.claude/skills/company-strategy-video/references/script-standards.md` 的「别把事实说过头」和「表达」两节。那份文件其余部分是给"只回答一个问题"的策略片写的，这里不适用。
- 中文稿写完用 `humanizer-zh` 过一遍。

## 原声放哪

- 一段 8–12 秒，一句完整的话。全片十段左右（Clay 23 分钟用了 12 段）。
- 用在"判断"上，不用在"事实"上：创始人解释为什么这么做、承认一个弱点、和主流看法唱反调。事实和数字由旁白讲。
- 原声前一句旁白要铺垫它（"Clay's CEO is surprisingly blunt about this."），后一句接住它（"So accuracy doesn't come from a promise."）。观众要知道这段话是来证明什么的。
- 只用本人真实说过的话。Janet 问过能不能克隆创始人的声音来念旁白，没有做：那等于替真人说他没说过的话。想要更多"本人出镜"，就多找真实片段。

## script.json 格式

```json
{
  "lang": "en",
  "voice": "male",
  "scenes": [
    { "id": "hook", "title": "Cold open", "segments": [
      { "vo": "一段旁白，可以好几句。" },
      { "clip": "founder_key" },
      { "vo": "接住原声的下一段旁白。" }
    ] }
  ]
}
```

- `lang`：`en` 或 `zh`。`voice`：`male` 或 `female`。可选 `speed`。
- 一个 `vo` 是一口气说完的一段，中间换画面靠卡点，不用拆段。要插原声或要明显停顿的地方才另起一段。
- `clip` 的值是 `clips.json` 里的 key。
- `title` 会显示在占位画面和审片时间线里。
