# 10 步框架：怎么讲透一个术语

原则：先讲用在哪，再讲是什么；先讲技术，再讲钱，最后讲风险。每一步一句话能说清就不说两句。观众是聪明但不懂技术的人。
框架 2026-10-27 和 Janet 一起定稿（她补了商业模式、创业公司、横向/纵向、风险）。

## 开场白（每一期都要，Janet 2026-11-05 定）

片子最前面约 15–20 秒，按这个顺序，不讲长例子：
1. **这一期你能学到什么**：一句话列 2–3 件事（如「这一期你会弄懂三件事：工具调用是什么、它和 agent 什么关系、谁在靠它赚钱」）。
2. **直接入主题**：大模型能做什么、不能做什么（或这期术语要解决的那个缺口），一两句。
3. **引出术语**：一句话点名这期的术语。
具体场景（纸鹤家居、订单号）放到后面「它是什么」里再用，不要放在开场铺垫。
起因：第 5 期开场先讲了 17 秒的客服例子，Janet 嫌啰嗦。

**开场的画面：先亮一次这期的全图（Janet 2026-11-05 定，第 5 期 v5 起）**
- 第 1 步「这一期你能学到什么」那句，画面不用便签列表，而是**先把这期后面会讲的那张全图整张亮出来**（已经摆好，不用一块块搭），让观众一眼看到这期要讲哪几块。
- 左边一列写「这期弄懂 N 件事」，念到第几件，左边写出那一条，**同时图上对应的部分亮起来**（开始动、画上圈、贴上粉色标签）。例：第 5 期念「工具调用」信封开始转圈，念「agent」画出大圈，念「谁在赚钱」三家公司的标签依次出现。
- 全图优先用纸模型 3D（`references/paper-3d.md`）；这期没有 3D 全图时，就用这期正片里「全图 / 一句话记住」那一幕的手绘图。所以**写脚本时先想好这期的全图长什么样**，开场和正片共用同一张。
- 正片讲到全图那一段再一块一块搭起来讲细节，开场只是预告，不讲细节。
- 做法参考第 5 期 Remotion：`~/AI-Terms/ai-tool-use-ep5/remotion/src/scenes/Hook.tsx`（h2 预览）和 `_fullpicture3d.tsx`（开场和全图共用的 3D 组件，时间表全设成负数 = 一开始就摆好）。

## 技术篇：它是什么

**① 解决什么问题（场景 → 老办法卡在哪）**
找一个人人见过的具体场景，带具体数字，再演示老办法失败的那一刻。
Embedding：给公司做客服机器人，500 份文档，顾客问"钱能要回来吗"；按字找，"钱要回来"对不上"退款"。最后一句点出需要的新能力："所以电脑需要……"

**② 它是什么（一个比喻 + 名字由来）**
只用一个贯穿全片的比喻（Embedding = 意义地图）。然后：
- **先分清"它是什么"和"拿它做什么"**，各一句话。场景通常演示的是用途，观众很容易把用途当成定义（Janet 看完第 1 期就以为 Embedding = 找相近词；其实 Embedding 只负责变成坐标，找相近是另一步）。用一个比喻说明两者关系（GPS 坐标 vs 找附近的餐厅）
- 把中文名 / 英文名拆开解释（向量 = 那串数字；嵌入 = 放进地图）
- 一句诚实的脚注，说明比喻简化了什么（"其实有上千维，画成平面只为好懂"）
- 只适用于文字吗？能不能用在图片、声音、商品 / 用户上（Embedding：以图搜图、找相似的歌、推荐）
- 一句历史：它从哪来、以前是什么样（Embedding：2013 年 word2vec 只放单个词）

**③ 怎么用、自己做还是买现成的**
三步以内，接回场景（准备 → 提问 → 找最近的），提一下行业里这套做法叫什么（RAG）。然后：要自己做吗？谁在卖、怎么接（API）、多少钱（一个真实价格）。HTML 页这里放成本计算器。

## 商业篇：谁靠它赚钱

**④ 链条：谁卖、谁存、谁买**
上游卖什么 → 中游卖什么 → 下游谁买来装进产品 → 最终用户得到什么。每层 2–4 个真实公司名。有收购就点出来（说明链条在合并）。

**⑤ 商业模式：怎么收钱**
每一层各靠什么赚钱，说清楚是哪一种：
- 按量收费（API 按 token / 次数）
- 订阅 / 按座位
- 开源免费 + 云服务或企业版收钱
- 卖给大公司做组件，或者被收购
- 打包进别的产品，不单独收钱
再点一句：利润厚不厚、靠量还是靠单价（Embedding：两美分一百万 token，靠量）。

**⑥ 玩家：大厂和创业公司**
大厂是谁（各列 2–4 个）；**创业公司有哪些**，每家一句话说它的切入点和最近一次融资 / 收购（有公开数字才写）。

**⑦ 门槛：做出来难在哪**
原理难不难懂 vs 做到第一梯队难在哪。讲清"它是怎么被训练 / 造出来的"，配一个可感知的数字（E5 约 2.7 亿对）。常见门槛：数据、算力、底座模型、榜单成绩、渠道 / 客户关系。有公开排行榜就讲它是什么。

**⑧ 横向还是纵向**
这个赛道是做通用的（横向，什么行业都卖），还是钻一个行业（纵向，法律 / 金融 / 医疗）？两条路各是谁在走，各自的优势（横向靠规模，纵向靠行业数据和贴身服务）。如果这个术语没有明显的纵向玩法，一句话带过。

**⑨ 拆一家：一个案例讲透**
挑一家创业公司（最好是纵向的那家），讲它具体怎么做（Voyage AI 的"三层楼"：通用 → 法律版 → 给 Harvey 定制）。只写公开资料能讲清的，数字注明是公司自报，**不编训练配方**。

## 风险篇：会不会被淘汰

**⑩ 风险与趋势**
两三句，挑这个术语真正面临的风险讲，不凑数。常见几类：
- **被大模型吃掉**：大模型越来越强，这一层还需要吗？（例：上下文窗口变长，RAG 还要不要）
- **商品化 / 价格战**：大家都差不多，价格往零走，利润在哪
- **被平台整合**：数据库、云厂商直接内置，独立公司被收购或挤压
- **技术路线被替代**：有更好的做法出现
- **合规 / 数据**：版权、隐私、行业监管
结尾给一个判断：这一层未来更值钱还是更不值钱，为什么。分清事实和观点，观点要说是观点。

## 收尾

一句话记住，**说的是它是什么，不是它能干什么**（"Embedding 是把东西变成意义坐标的那一步；有了坐标，才能按意思找东西"）+ 一行串起商业链（"模型公司卖它，数据库存它，软件公司装进产品"）+ "收藏起来"。

## 脚本格式（SCRIPT.md）

```
## <scene>
<id> | 中文台词 | English caption
```

- 一行 = 一句配音 = 一组字幕。中文每句 ≤ 40 字，读起来像聊天。
- 场景名就是 compositions/<scene>.html 的文件名；id 用场景首字母 + 序号（h1、s1…）。
- 一个步骤可以是一个场景，也可以拆成两个（第 1 期把①拆成 scene + problem）。
- 英文版单独写 `id | English line`，按口语重写，不逐字翻译，id 保持一致，场景提示点才能对上。
- 时长参考：中文约 4 字/秒，英文约 2.7 词/秒（1.1 倍速）。第 1 期中文 63 句 ≈ 5 分钟。**没有时长目标**：优先把术语讲清楚，不要为了压时长删掉帮助理解的解释（Janet 2026-10-27 定）。时长只用来告诉 Janet。

## 研究清单

- 定义和名字由来（中英文都要）
- 一个能贯穿全片的日常场景
- 价格（官方价格页）
- 产业链上中下游各 2–4 家，收购事件
- 每一层怎么收钱
- 创业公司名单：切入点、融资 / 收购（公开数字）
- 训练 / 制造方法，带一个数字（论文）
- 公开排行榜
- 横向 vs 纵向各有谁
- 一家创业公司的公开案例（官方博客），数字注明来源
- 风险：分析文章、创始人 / VC 的公开观点（注明是谁说的）
- **来源要准确**：优先一手来源（官方新闻稿、官网、论文、原始播客/帖子）；只有二手转述的，换成一手或不写进台词
- **真实画面清单**（视频右栏的纸上屏幕，见 `visual-direction.md`）：
  - 这期"真跑一次"跑什么（场景里老办法失败 + 新办法成功，都要真实结果）
  - 要截的一手页面：官方价格页那一行、官方文档、公司技术博客 / 案例页、公开排行榜
  - 链条和玩家里每家公司的官方 logo（press kit 链接）
- 全部链接写进 BRIEF.md 和 HTML 页的「资料来源」
