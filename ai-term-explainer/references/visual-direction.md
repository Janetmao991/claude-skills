# 视觉方向：纸上类比 + 纸上屏幕（2026-10-28 和 Janet 定）

一句话：**类比负责让人记住，真实画面负责让人相信，两者都待在同一张纸上。**
样板：`~/Adal/ai-embedding-ep1-wide/`（横屏，前两分钟）→ `~/HyperFrames Video/exports/embedding-横屏-前两分钟.mp4`

## 为什么这样定（试过、放弃过的）

| 试过 | 结果 | 结论 |
|---|---|---|
| 白板 + 小机器人角色 + 字幕下方小窗口 | 一屏四样东西抢注意力，真实窗口像贴纸 | 不要角色；一屏一个焦点 |
| 切到全屏深色"真实场景"（暗背景 + 原样网页截图） | 有动感，但纸面质感一下断掉，像在切幻灯片 | 不离开纸面 |
| 全片"高级科技风"（玻璃、光影、粒子） | 没做，判断会抢走理解力 | 讲解视频不用 |
| **纸上类比 + 纸上屏幕（A+C）** | 风格统一，类比和证据分得清 | ✅ 默认 |

背后的规律：Mayer 多媒体学习的**一致性原则**，和内容无关的装饰（再好看）都会让人学得更差。每一个会动的东西都要在"说意思"，不是在装饰。

## 画幅

- **默认横屏 1920×1080**：X 直接发；小红书也能发（横屏显得更专业），但要单独做 3:4 竖版封面。
- 小红书想让竖着刷的人也看得清：做**竖屏包装版** 1080×1920（横屏画面居中，上方放大标题，下方放大字幕，上下用同样的纸面填满，不留黑边）。为此横屏再渲染一份**不带字幕**的版本。
- 竖版 1080×1920 仍可用（第 1 期），但新一期默认横屏。

## 纸上屏幕（真实画面的唯一出场方式）

出场顺序：手绘框画出来（0.45 秒）→ 两条胶带"啪"贴上 → 屏幕滑入 → 屏幕上方逐字写出一句**手写结论**（关键数字用粉色）→ 屏幕里的真实操作动起来 → 配音停顿 2–2.5 秒让人看 → 整块淡出，纸面恢复干净。

- **配色跟纸走**（以下面「品牌规范」为准）：米白底 #fffdf7、深灰 #2E2E33 边框和按钮、粉 #E5466E（问题 / 关键数字）、黄色荧光 rgba(255,212,59,.45)（重点）；不用蓝。字体：界面用苹方（`local("PingFang SC")`），代码和数字用 JetBrains Mono，手写结论用画板字体。
- **一个镜头只证明一件事**，结论一句话 ≤ 20 字，带一个真数字：「按字搜 **0** 条结果」「一句话 → **1024** 个数字」「离问题最近的：**退款流程 0.609**」。
- **用操作动效代替静态图**：光标点进输入框 → 逐字打字 → 点按钮 → 结果一条条出来 / 分数条涨起来 / 数字流回来 / AI 逐字回答。动效本身就是讲解。
- **配音停顿**：真实镜头所在那句台词后面插 2–2.5 秒静音（`templates/wide/build_holds.py` 的 `HOLDS`），整条时间轴自动后移。一期前两分钟大约加 15–20 秒。
- 屏幕块的时间表只写在 `assets/real-blocks.js`（`REAL_BLOCKS`，按台词 id 计算），字幕、场景都从这里读。

## 公司和创业公司：用真实 logo

讲链条、玩家、收购时，公司名不要只写小字，用**真实 logo 卡片**：
- 一家公司 = 一张白色便利贴卡（略倾斜、带一条胶带），上面是官方 logo + 一行手写说明（切入点 / 融资 / 被谁收购）。收购用手绘箭头把两张卡连起来（例：MongoDB ← Voyage AI）。
- logo 来源：公司官网的 press kit / brand 页，或官网页头的 SVG；存进 `assets/logos/<company>.svg|png`，在 BRIEF.md 记下来源链接。
- 原样使用（不改色、不变形、不拼接），只用来指认这家公司，不暗示合作或背书。拿不到清晰官方 logo 的，就用手写公司名，不要用第三方图标站的仿制品。
- 一屏最多 4–6 张卡，多了分两拍出场。

## 三样手绘质感（2026-10-28 试过；镜头默认开，笔和画画声音默认关）

样板：`~/Adal/ai-embedding-ep1-fx/` → `exports/embedding-横屏-前两分钟-手绘质感.mp4`（对比片 `embedding-手绘质感-前后对比.mp4`）。工具都在 `templates/wide/`：

| 效果 | 怎么做 | 文件 |
|---|---|---|
| 笔尖跟着画（**默认关**：Janet 说笔会分散注意力；`SK.SHOW_PEN = true` 才画出来） | `fx.js` 包住 `SK.draw` / `SK.write`：记下每一笔的路径，一支白板马克笔沿路径走、写字时左右起伏，两笔之间抬笔移过去，停下淡出；笔帽颜色跟墨色。每个场景脚本里 `SK.penStart(svg.parentNode, 1080, 1920, 场景开始秒, 1.0715, [0.9333, 16, -193.5])`，最后 `SK.penFinish(tl, 场景时长)`。**同一时间只能有一支笔**：右栏屏幕不接笔 | `fx.js` |
| 镜头跟着讲解 | 每个场景内容包进 `<div id="xx-cam">`，脚本末尾 `SK.camera(tl, "#xx-cam", 场景开始秒, 场景时长)`；关键帧由 `build_camera.py` 按笔画位置自动生成（这句台词画在哪就轻推到哪，1.1 倍；屏幕出现时转向右栏 1.08 倍；换段落拉回全景）。字幕、进度链不跟镜头动 | `build_camera.py` → `assets/camera-keys.js` |
| 画画的声音（**默认关**：Janet 2026-10-28 第 3 期说沙沙声太大；要开就把 `build_film.py` 的 `DRAW_SOUND` 改成 True，并把 `build_drawsfx.py` 音量调低） | `dump_strokes.sh` 开预览、无头 Chrome 读出全片笔画（时间、时长、画线还是写字、位置）→ `build_drawsfx.py` 按笔画合成一条音轨（画线 = 马克笔沙沙、写字 = 笔尖、贴屏幕 = 胶带），根合成里加一个 `<audio id="sfx-draw">`，音量 0.7 | `dump_strokes.sh`、`build_drawsfx.py` → `assets/sfx/drawing.wav` |

顺序：场景改完 → `dump_strokes.sh` → `build_camera.py` → `build_drawsfx.py`（要用带 numpy 的 Python，如 `~/.cache/mlx-audio-venv/bin/python`）→ check → 渲染。场景或台词一改，三步都要重跑。
- 现在的声音是程序合成的（噪声 + 滤波），有感觉但不如真录音；以后可换成 CC0 实录音效，`build_drawsfx.py` 里换掉三个合成函数即可。
- **镜头不要每句都推**（参考 `huashu-art-motion` skill 的 `references/镜头语言.md`：镜头是标点；有推就要有拉；不要连着往里推；观众在读字、画面自己在动时镜头停住）。第 1 期自动生成了 35 个关键帧，偏多，下一期把 `MIN_SHIFT` 调大，或只在换想法时推。

## 其余可以试的巧思（按值得做的程度排）

1. **笔尖跟着画（默认关，Janet 2026-10-28：笔会分散注意力）**：场景脚本照样调 `SK.penStart` / `SK.penFinish`（它们负责记录笔画，镜头和声音靠这份记录），只是不画笔；某期确实要笔时设 `SK.SHOW_PEN = true`。一支马克笔（白板）或钢笔 / 铅笔（方格本、牛皮纸）的小图，笔尖沿线条路径走（SVG `getPointAtLength`），写字时沿着字的揭开方向移动。羽毛笔偏复古，只配牛皮纸、羊皮纸类画板。最能让观众感觉"有人正在画给我看"。
2. **画画的声音**：画线配马克笔沙沙声，写字配笔尖声，贴屏幕配撕胶带声，盖章配"咚"，换场景配翻纸声。声音对质感的提升往往比画面大。音效用 CC0 素材或 `/media-use` 生成，音量压在配音下方。
3. **镜头跟着讲解走**：画到哪推近到哪（轻推 1.1–1.3 倍），讲完拉回全景。动感来自"看的地方在变"，而且每次推近都是在指"看这里"。
4. **换场景像翻页 / 擦白板**：用翻页、擦除、新纸滑入代替硬切，全片固定用一种。
5. **线条轻微抖动（line boil）**：手绘线每 3 帧换一个随机种子重画（固定种子序列，保证每次渲染一样），像手绘动画那样"活着"。幅度要小，只用在静止较久的画面上。
6. **纸张和墨水**：极淡的纸纹理叠加、荧光笔边缘不齐且用正片叠底盖住文字、贴上去的东西有很轻的投影。
7. **写错再划掉**：偶尔先写错再划掉改对（例：先写「钱要回来」，划掉，旁边写「退款」），正好表达"误解 → 正解"。一期最多一两次。
8. **笔的颜色有固定含义**：深灰 = 正文和箭头，粉 = 问题 / 关键数字，黄荧光 = 重点（见「品牌规范」）。

1、2 默认关（笔、声音），3 默认开；4–8 新做时先出一段 20 秒对比给 Janet 看再推广。

## 品牌规范（2026-10-28 Janet 补充的四点）

**配色**
- 纸底浅米黄 **#FAF4E8**（2026-10-28 Janet 要比 #F5EBD7 再浅一点；更早是 #F6F0E4）。背景叠一层很淡的纸纹（`boards/paper-texture.txt`，所有浅色画板统一用），**不要方格、点阵、横线**（Janet 2026-10-28）。
- 线条和文字用**深灰 #2E2E33**，不用纯黑 / 接近纯黑的 #1E1E24。
- **全片最多两种强调色，就是品牌色：粉 #E5466E（问题、关键数字、重点）+ 黄荧光 rgba(255,212,59,.45–.75)（划重点）。** 蓝色 #2E7CF6 退役：箭头、流程线改用深灰；屏幕里输入框聚焦、用户气泡、分数条改用深灰或粉。（⚠️ 和旧规则冲突：第 1 期和横屏版都用了蓝色。）
- 例外：坐标图里区分不同类别的点，可以用灰阶 + 粉，不加新颜色。

**线条**
- 保留 rough.js 的抖动和粗细不均；静止超过 2 秒的画面加轻微 line boil（见巧思 5），幅度小。

**节奏**
- 一句台词对应一个新元素；一幕只讲一个概念。
- 画完停 0.5–1 秒再转场；真实屏幕另外按上面的规则停 2–2.5 秒（屏幕里一直有动作，不算"停住不动"）。
- 每 3–5 秒画面要有新东西出现（竖版尤其要守；横屏也照这个检查：快照里连续 5 秒画面没变化的地方要补一个动作）。

**字体**
- 标题、关键词、手写结论：手写体（画板字体，如 Hannotate SC）。
- **字幕和屏上正文：中文圆体 Yuanti SC 常规（400），英文 SF Pro（`system-ui`），不加粗**（2026-10-28 Janet 从 苹方 / 圆体 / 楷体 / 手写体 对比里选的圆体：比苹方灵动，又清楚好读）。字体文件要导出到项目 `assets/fonts/yuanti-sc-regular.woff2` 并写 @font-face（见 production.md 第 3 期的坑）。标题和关键词仍用画板手写体。
- 强调用**手绘的圈、下划线、荧光笔**，不靠加粗。⚠️ 纸上屏幕里有几处加粗（按钮、前两名、结论数字），新一期改成粉色 + 手绘下划线。

## 不要做

- 不要角色 / 吉祥物（Janet 2026-10-28：不需要机器人）——指的是贯穿全片、和内容抢注意力的「主持人」。
- **但画面里的物要画成它本来的样子，不用「方框 + 文字标签」代替**（Janet 2026-10-30：要拟物化）。客服机器人画成戴耳麦的机器人、文档画成纸、数据库画成圆柱。先查道具库 `assets/props.js` 和 Excalidraw 素材 `assets/props-ex.js`（目录见 `references/props.md`，挑图看 `props-src/excalidraw/sheet.html`），都没有的就画一个并存进去。
- **叠一张纸条补充细节时，先把背后的画板隐掉**（Janet 2026-10-31：纸条后面还看得到字，很乱）。标题保留，其余元素用 `filter: opacity(0)` 淡出，纸条拿走后再淡回来（用 filter，不碰元素本身的 opacity，还没写出来的字就不会提前冒出来）。写法见 `~/AI-Terms/ai-rag-ep3/tools/add_rag_vs_embedding.py`。
- 不要切到全屏深色"真实世界"；不要原样贴别人家网站当主画面（证据截图除外，而且要放进纸上屏幕）。
- 不要在一屏里同时放类比、真实界面、角色和大段文字。
- 不要编数字。屏幕上的每个数字都来自真实运行结果或一手来源；公司自己说的数字（如 Airbnb 博客写"搜索排序和相似房源带来 99% 的预订转化"）要标明是公司自报。
